# Vorbestellungen über Redis / заказы через Redis

Цель: ускорить загрузку списка заказов и создание предзаказа. Таблица `Orders` остаётся источником правды,
SMS-напоминания и всё остальное продолжают читать её. Архитектура та же, что у Lehrlinge (`lehrlinge/VERCEL-SYNC.md`).

```
Чтение:  Sheet ──(GAS orders_sync.gs, каждые 5 мин / после записи / onEdit)──▶ /api/orders?op=sync ──▶ Redis
         браузер ──▶ /api/orders?op=list|todos ──▶ Redis        (при любой проблеме: прежний путь через GAS)
Запись:  браузер ──▶ /api/orders?op=create|update|status ──▶ Redis + очередь (ответ ~0,2 с)
                                                              └─ в фоне ──▶ GAS ──▶ Sheet (по порядку, с повторами)
```

## Принципы безопасности
- **Выключено по умолчанию.** Пока нет env `ORDERS_REDIS=on`, все эндпоинты отвечают 503 и клиент ходит в GAS.
  Запись включается отдельно: `ORDERS_REDIS_WRITES=on`.
- **Любой сбой ведёт на GAS.** Снапшот в Redis живёт 30 минут: если синхронизацию выключить, чтение вернётся на GAS само.
  На устройстве можно принудительно вернуться на GAS: `localStorage.setItem("mt_orders_redis", "off")`.
- **Создание без дублей.** Клиент шлёт `requestId`; повтор с тем же ключом и теми же данными возвращает тот же ответ.
  На GAS клиент откатывается при создании только если сервер точно ничего не принял (503/404). При неясном
  результате (обрыв сети, 5xx) показывается «Verbindung unklar – bitte noch einmal auf Speichern tippen».
- **Импорт в таблицу идемпотентен** (`orders_import`): тот же номер с тем же содержимым пропускается; при коллизии номера
  GAS выдаёт новый номер, Redis переименовывается.
- **Порядок операций сохраняется** (создать → изменить → статус). Временная ошибка останавливает очередь, повтор при каждой
  записи и при каждой синхронизации (≤ 5 мин); после 8 попыток или окончательной ошибки GAS запись уходит в `orders:outbox:dead`.
- **Снапшот не затирает** заказы из очереди и записанные менее 2 минут назад.
- Только `orders_import` требует серверный ключ (`SYNC_SECRET`); обычные `create/update/status` через GAS работают как раньше.
- Все эндпоинты заказов объединены в одну функцию Vercel (`api/orders.js`), чтобы не выйти за лимит функций тарифа.

## Номера заказов
Трёхзначные номера (100–999) заканчивались: на 22.09.2026 занято 375 из 900 (~19 в день). Теперь при исчерпании
трёхзначных выдаются четырёх-, затем пятизначные (GAS `orderId_` и Redis `pickOrderId`).

## Включение (по порядку)
1. Запушить код (ничего не меняется, всё выключено).
2. GAS: `clasp push` и **новая версия деплоя** веб-приложения. Script Property `SYNC_SECRET` уже задан (тот же, что для Lehrlinge).
3. Vercel → Environment Variables: `ORDERS_REDIS=on`, Redeploy. Пока снапшота нет, сайт получает 503 и ходит в GAS.
4. GAS: Script Property `ORDERS_SYNC_ENABLED` = `true`; запустить **`installOrdersSyncTriggers`**
   (триггер каждые 5 минут + onEdit, сразу отправляет первый снапшот). В журнале: `Orders sync: {"ok":true,"orders":…}`.
5. Проверить чтение: `node scripts/compare-orders.mjs`, ожидается «Alles gleich». Открыть «Bestellungen» и «Nächste»: список должен появляться быстро.
6. Наблюдать сутки. Затем включить запись: Vercel `ORDERS_REDIS_WRITES=on`, Redeploy.
7. Проверка записи: создать тестовый заказ, увидеть его в списке сразу и в таблице через несколько секунд; отменить его; создать «Mo–Fr nächste Woche» и повтор «Jede Woche».

## Откат (от быстрого к полному)
| Что | Как |
|---|---|
| Только запись | Vercel: убрать `ORDERS_REDIS_WRITES`, Redeploy. Очередь дослать: `sync` сам её сливает |
| Всё (чтение и запись) | Vercel: убрать `ORDERS_REDIS`, Redeploy (клиенты сразу переходят на GAS) |
| Один телефон | `localStorage.setItem("mt_orders_redis","off")` |
| Остановить синхронизацию | GAS: `removeOrdersSyncTriggers`, убрать `ORDERS_SYNC_ENABLED`; копия истекает за 30 мин |
| Код | `git revert` коммитов «Orders …» или тег `pre-orders-redis` |

## Наблюдение
- Ответ `sync` (и журнал GAS `Orders sync: …`) содержит `outbox: {pending, dead}`: `pending` обычно 0, `dead` должно быть 0.
  `dead > 0` пишет предупреждение `WARNUNG Orders outbox` в журнал GAS.
- Мёртвые записи лежат в Redis: `orders:outbox:dead` (поле, JSON с причиной).

## Ограничения
- Поиск (`search`) по-прежнему идёт через GAS.
- Общий секрет API (`102030`) лежит в клиентском коде, как и раньше: это не защита, а отметка «наш клиент». Стоит перейти
  на вход водителя (JWT), как у Lehrlinge, отдельной задачей.
- Напоминания по SMS читают таблицу: заказ попадает туда в течение секунд после создания (очередь), но не мгновенно.
